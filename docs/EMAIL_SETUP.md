# Email setup (Resend + Supabase)

DAYBREAK sends two kinds of email:

| Email | Sent by | When |
|---|---|---|
| Sign-up confirmation, magic link | **Supabase Auth**, through Resend's SMTP server | On email sign-up, on "Resend link", on magic-link sign-in |
| One-time welcome | **DAYBREAK's server**, through Resend's API (`RESEND_API_KEY`) | After a reader's **first** Google sign-in only |

Google accounts are already verified by Google, so they are never asked to confirm their email again.

## 1. Resend

- Sending domain: **`tehsaad.site`**, already verified in Resend with sending enabled.
- Create a dedicated API key: **Resend → API Keys → Create**.
  - Name: `daybreak`
  - Permission: **Sending access**, domain `tehsaad.site`
  - Copy it once; you'll paste it in two places below.

## 2. Supabase → Authentication → Emails → SMTP Settings

Turn on **Enable custom SMTP** and enter:

| Field | Value |
|---|---|
| Sender email | `hello@tehsaad.site` (any address on the verified domain) |
| Sender name | `DAYBREAK` |
| Host | `smtp.resend.com` |
| Port | `465` |
| Username | `resend` |
| Password | the Resend API key from step 1 |

Then, under **Authentication → Rate Limits**, raise "Rate limit for sending emails" from Supabase's default (a few per hour) to suit your traffic.

## 3. Supabase → Authentication → Emails → Templates

Paste these files, generated by `npx tsx scripts/build-email-templates.ts`:

| Template | Subject | Body |
|---|---|---|
| **Confirm signup** | `Confirm your email for DAYBREAK` | `supabase/templates/confirm-signup.html` |
| **Magic Link** | `Your DAYBREAK sign-in link` | `supabase/templates/magic-link.html` |

The links use `{{ .SiteURL }}/auth/callback?token_hash={{ .TokenHash }}&type=email`. They are verified server-side by `/auth/callback` and work even when the email is opened in a different browser from the one used to sign up. This depends on **Site URL** being `https://daybreak-gilt.vercel.app` (Authentication → URL Configuration).

Supabase's template system sends HTML only. Each template therefore includes the full link as visible text under the button, as a plain-text fallback.

## 4. Vercel → daybreak → Settings → Environment Variables (Production)

| Name | Value | Type |
|---|---|---|
| `RESEND_API_KEY` | the Resend API key from step 1 | Sensitive |
| `RESEND_FROM_EMAIL` | `DAYBREAK <hello@tehsaad.site>` | Plain |

Without these two, everything still works; the welcome email is just skipped, and it is not marked as sent, so it can go out once they're configured.

## How the states look to a reader

| Situation | What the reader sees |
|---|---|
| Just signed up | "Check your inbox…" plus a **Resend link** form, prefilled from a 1-hour httpOnly cookie |
| Clicked an old or used link | "That sign-in link has expired…" plus **Resend link** |
| Tried to sign in before confirming | "Please confirm your email address first…" plus **Resend link** |
| Asked to resend too soon | "Please wait a minute…" (60-second cooldown per address, plus per-IP rate limits) |
| Confirmed | Signed in, taken to onboarding with "Email confirmed — welcome to DAYBREAK" |
| First Google sign-in | Signed in straight away; one welcome email, never repeated (see below) |

**Welcome email de-duplication.** The OAuth callback runs `update profiles set welcome_email_sent_at = now() where id = <user> and welcome_email_sent_at is null`. Only the request that changes a row sends the email, and it sends after the redirect, so sign-in isn't slowed down. The send also carries a Resend idempotency key, `daybreak-welcome-<user id>`. If sending fails, the claim is released so a later sign-in can retry.
